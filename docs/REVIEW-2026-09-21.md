`docs/STATUS.md` is 651 lines. Sections "Works", "Does not", "Next", "Not verified" and "Numbers" fit in the first 98. The other 554 are "Recent": sixteen dated entries, each a rewrite of a commit message, some with tables of centroid spreads and pixel counts. ### 4.2 The archive is not frozen

`docs/history/README.md` says "Nothing here is current" and "never read one of these whole". Then `45926ef` appended 605 lines to `current-task-archive.md`. It is 704 KB now. Once a file is history, it does not take new entries.

### 4.3 Prose where a mechanism belongs

`docs/VERIFYING.md` says it best, about itself: "At least four of these lessons were written down and then broken anyway... Prose did not stop any of them. The lessons that stopped recurring became mechanisms." Six more rules (90 to 95) were added in two days. Three commits (`7461701`, `6f5496b`, `1969d97`) went to the screenshot instrument; the next code commit came seven hours after the first of them.

**Fix:** the screenshot stays mandatory. It is what caught the four defects every numeric check passed (the heading 160 px off, the vanished tab strip, the transposed labels, the list rebuilt every frame), and it is what would have caught bug 1 below. What should stop is re-diagnosing the capture harness by hand each time it disagrees. Make the harness enforce rules 90 to 92 itself: it refuses to grab while the game is paused, it measures the control floor before it quotes a percentage, and it photographs a known-drawn cell first. A grab that fails those checks is rejected by the tool, not debated in a commit.

### 4.5 The code patterns the last review named, repeated in the new code

- **Packed cell id decoded by hand**, three more times: `ParkPicking.cs:63-64`, `:173-174`, `:308-309`, while `MapStep.CellId` and `CellAt` exist and the file's own remark says so.
- **Guest and staff duplicated again.** `ParkPeople.Hire` (`:430-438`) is `Admit` (`:330-338`) copied for staff, navigator block and sprite block verbatim.
- **The eight-direction table twice**: `ParkPathNeighbours.cs:43-53` and `ParkPathBuilding.cs:438-442`.
- **`KindFor` re-implements `StaffState.PayTypeOf`** (`ParkStaffPool.cs:178-186` vs `ParkWorld.cs:552-560`), with a comment saying "the two must agree".
- **The same resolve-level-state-park-item guard 13 times** across `ParkBuilding`, `ParkPathBuilding`, `ParkItemsScreen`, `ParkObjectWindow`.
- **Per-screen scaffolding copied four times**: `CrossLink()` in four screens with identical bodies; the tab loop in four; a `static _lastTab` per screen beside `ParkCategoryScreens.LastLeftOn`, which already remembers the screen.
- **Changelog voice in new code**, 24 hits: "this paragraph said for months", "RESOLVED 2026-09-21", "the first version copied". `ParkObjectWindow.cs:733-754` is a debugging narrative with the instrumentation it describes still executing at `:755-800`. `ParkState.cs:141-153` has two `<summary>` blocks on one method.

### 4.6 New patterns worth stopping early

- **Strings as return values, parsed by the caller.** `ParkBuilding.cs:171` tests `sold.StartsWith( "sell: '" )`; `:310` tests `answer.Contains( "built as thing" )`; `Level.RunBuildMode` tests `Contains( "laid at" )`. A reworded message silently breaks a caller. Return a result enum and a message.
- **Static verbs that reach for `Level.Current`.** `ParkBuilding`, `ParkPathBuilding`, `ParkPicking`, `ParkBuildMode`, `ParkSurfaces` are all static classes; 31 `Level.Current` reach-ins in the new files. `ParkPathBuilding`'s private helpers already take `(state, park)` as parameters; the public verbs should too.
- **Four separate "what is in the hand" states**: `ParkBuilding.Carrying`, `ParkStaffPool.Carrying`, `ParkPeople._carriedStaff`, `ParkBuildMode.Current`. `Level.ClickWorldAt` tests them in a fixed order.
- **The debug console is one 1,040-line switch.** 26 of the 38 new commands exist only so the capture harness can click, pick, carry and put without a mouse.
- **Every new test needs the game.** 48 new tests, 0 runnable without it. The project's own rule is to extract the decision into a pure function and pin that. These tests are regression protection so a fix stays fixed; they are not proof a feature works. Proof is the screenshot and the census, both.

## 5. Six bugs in the new code

Each was found by the code-read agent and then checked by me against the source. Line numbers are at `1fd83ad`.

| # | Where | What | Effect |
|---|---|---|---|
| 1 | `ParkPeople.cs:1228, 1358, 1426, 1523` | The ride-turn sweep, the invite walk and the census iterate `world.Objects`, the immutable save list. `ParkState.AddObject` (`ParkState.cs:198`) holds bought objects, and nothing simulation-side reads it. `ParkRideChoice.Offerable` (`ParkRideChoice.cs:406-423`) walks the save's `FirstObject/NextObject` chain. | **A ride bought this session binds its script and animates, but never takes a turn, is never offered to a guest, and never sells a ticket.** STATUS line 32 says "Things can be bought" without this caveat. |
| 2 | `ParkPathBuilding.cs:251-257`, `:426-427` | `LayQueue` writes `Type`, `TileSet`, `Direction`, `ParentId` but not `Neighbours`, `TileIndex` or `TileAngle`. `Retile` returns for anything that is not a path, and the queue table in `ParkPathTiles.TileFor` is called from nowhere. | **A laid queue draws piece 0 at 0° in every cell and cannot be walked**: `CellEdge.Blocked` (`CellEdge.cs:362-367`) refuses a queue cell whose mask lacks the facing bit. The three `ParkPathBuildingTests` never lay a queue. |
| 3 | `ParkBuilding.cs:163-177` | `Move` is `Sell` then `Buy`. | If the new cell refuses ("would not fit", "costs more than the park has"), the thing is sold, the refund is banked, and nothing is in the hand. `ParkObjectWindow.Move` (`:1246-1259`) does Sell-then-Carry and is fine; only the console verb has it. |
| 4 | `ParkBuilding.cs:134-135`; `ParkRides.cs` has no unbind | `Sell` removes the model and the state object. `ParkRides` keeps the script bound and scheduled. Queues keyed by the sold object's id are untouched. | The scheduler keeps running a script whose animation players point at deleted entities; any guest queued for it stays queued. |
| 5 | `ParkStaffPool.cs:95-100` | `PlaceCarried` does `Take` (removing the candidate) and `Carrying = 0` before `people.Hire`, which can return 0 (no sprite, off-map cell). | A failed hire destroys the candidate and reports "hired X as thing 0". The console's own `hire` case does it in the safe order and says why. |
| 6 | `Level.cs:851-858` | `Unload` forgets both cameras and `ParkBuildMode`, but not `ParkBuilding.Carrying` or `ParkStaffPool.Carrying`. | Leave a park mid-carry, enter another theme, click: the previous theme's catalogue id is placed. |
